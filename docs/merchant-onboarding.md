# 商户开通与对接流程

本文档用于运营、产品、技术支持和商户技术团队。它把管理后台的配置顺序、每一步需要填写的内容、配置之间的依赖，以及商户正式调用 API 的流程统一起来。

公网接口字段以 [`merchant-api.md`](merchant-api.md) 为准；本文档不重复定义接口字段，只说明如何得到接口调用所需的商户、产品和运行配置。

## 一、整体流程

平台配置和商户开通按下面的依赖顺序执行：

```text
系统与权限
    -> 国家/币种主数据
    -> 收款产品与产品能力
    -> 支付渠道与渠道能力
    -> 商户账户与商户资料
    -> 商户产品绑定（生成 App ID）
    -> 商户 API / WEBHOOK 凭证
    -> 路由、费率、风控规则
    -> 配置版本校验、审批、发布
    -> 商户联调、下单、通知、查询
    -> 结算规则与上线运营
```

其中：

- `productCode` 是平台内部产品编码，不对商户开放。
- `appId` 是商户产品绑定生成的公开下单标识，从 `1000` 开始，商户下单只传 `appId`。
- `payModel` 是商户选择的对客支付方式。平台根据产品能力将它映射为渠道支付方式，再选择实际渠道。
- 运行时必须使用已发布的配置版本；草稿或未审批的规则不会用于新订单。

## 二、管理后台配置顺序

### 0. 系统准备与权限

由平台管理员完成：

- 确认 Gateway、Platform、Trade、Fund、MySQL、Redis、Nacos、RocketMQ 和 MinIO 已按部署文档运行。
- 创建运营、风控、财务和只读角色，并分配最小权限。
- 确认操作审计、配置发布审批人和生产环境密钥管理方式。
- 生产环境禁止使用 `SIMULATED` 渠道或模拟签名方案。

配置、凭证和发布操作都应使用有数据范围限制的后台账号完成，不使用共享账号。

### 1. 国家、币种和国家-币种关系

后台入口：`国家与币种`。

先配置基础市场，再配置产品和渠道。内容如下：

| 内容 | 说明 |
| --- | --- |
| 国家/地区 | 两位国家代码、名称、区域、状态 |
| 币种 | 三位 ISO 4217 代码、名称、符号、金额小数位、状态 |
| 国家-币种关系 | 指定某个国家可使用哪些币种，并单独维护关联状态 |

只有 `ACTIVE` 的国家、币种及国家-币种关系可以用于新产品、产品能力和订单。停用不会删除历史订单数据。

### 2. 收款产品与产品能力

后台入口：`产品管理`。

先创建产品基本信息，再在同一页面配置产品能力。

#### 2.1 产品基本信息

| 字段 | 说明 |
| --- | --- |
| 产品编码 `productCode` | 平台内部唯一编码，例如 `CARD-US-USD`；仅后台和内部配置使用 |
| 产品名称 | 展示名称 |
| 产品类型 | 当前商户收单使用 `PAYIN`；出款产品当前未开放 |
| 接入模式 | `DIRECT` 直连或 `AGGREGATED` 聚合 |
| 默认国家/地区 | 必须是启用的国家 |
| 默认币种 | 必须是该国家已启用的币种 |
| 产品描述 | 运营和商户识别用 |
| 账单描述符 | 对账单或账单展示用，按平台长度约束填写 |

#### 2.2 产品能力

每条能力描述一种“商户可选方式”到“渠道提交方式”的映射：

| 字段 | 说明 |
| --- | --- |
| 对客支付方式 `customerPaymentMethod` | 商户下单时的 `payModel`，例如 `CARD` |
| 渠道支付方式 `channelPaymentMethod` | 供应商实际接收的支付方式，例如 `CARD_CREDIT` |
| 最小金额 / 最大金额 | 该方式允许的订单金额范围 |
| 退款能力 | 是否允许该产品能力进入退款流程 |

没有启用的产品能力不能被商户下单使用。不要把渠道专属字段放入产品能力；渠道专属参数只放在商户下单的 `channelParams` 中，并按已发布渠道协议约束。

### 3. 支付渠道与渠道能力

后台入口：`路由与渠道` 的渠道配置区域。

渠道配置决定平台如何调用供应商，不等同于商户 API 凭证。每个渠道至少填写：

| 内容 | 说明 |
| --- | --- |
| 渠道 ID | 平台内部唯一标识，创建后不随意修改 |
| 渠道名称 / 服务商 | 运营识别和审计展示 |
| 请求 URL | 供应商下单地址；真实渠道使用 HTTPS |
| 签名方案 | 选择已支持的签名 profile，并与供应商协议一致 |
| 接入参数 `configuration` | 超时、查询地址、金额精度、字段映射等非敏感参数 JSON |
| 渠道凭证 `credentials` | 商户号、应用标识、请求/回调密钥等敏感值 JSON |
| 渠道能力 | 国家、币种、渠道支付方式、最小金额和最大金额 |

`configuration` 和 `credentials` 的字段由供应商协议决定。不要在代码、日志、审计记录或普通说明中暴露真实密钥。以 PayProo 为例，当前校验要求 HTTPS 请求地址、`appId`、`queryUrl`、`amountScale`、`requestFields`、`requiredFields`、`methodMappings`，以及 `merchantSecretKey`、`merchantPrivateKey`、`platformPublicKey` 等凭证字段。

保存后先保持渠道停用，完成配置检查和路由绑定后再启用。生产环境启用前必须确认供应商白名单、回调地址、签名公钥和超时参数已完成联调。

### 4. 创建商户并登记商户资料

后台入口：`商户管理`。

先创建商户账户，再补齐商户资料和联系人。

#### 4.1 商户账户

- 商户名称。
- 商户状态：新商户完成资料和开通检查后再启用。
- `merchantId` 是平台运行时稳定标识，可由后台或数据库生成；不作为商户下单的公开产品标识。

#### 4.2 商户资料

建议至少填写：

- 法定名称、主体类型、注册国家/地区。
- 行业或 MCC、业务网站、商品或服务描述。
- 账单描述符、风险等级、税务识别号。
- 支持邮箱、支持电话、支持网站。
- 注册地址、城市、省/州和邮编。

#### 4.3 商户联系人

分别登记运营、财务、技术和法务联系人，维护姓名、邮箱、电话和是否接收通知。技术联系人应能处理签名、回调和接口故障；财务联系人应能处理结算和对账问题。

### 5. 绑定商户产品并取得 App ID

后台入口：`商户产品`。

新增绑定时选择启用中的商户和启用中的产品。绑定成功后平台生成商户专属 `appId`：

- 从 `1000` 开始，至少四位数字。
- 历史绑定已经重新编号，新绑定继续自增。
- 同一商户不能重复绑定同一产品。
- 停用绑定后，该商户不能用对应 `appId` 创建新订单，但历史订单仍可查询。

后台列表必须向运营展示 `App ID`、商户、产品、可用支付方式和绑定状态。将这个 `appId` 提供给商户，不能把 `productCode` 提供给商户作为下单参数。

### 6. 生成商户凭证

后台入口：商户详情 -> `API 凭证`。

至少准备两类凭证：

| 凭证 | 用途 |
| --- | --- |
| `API` | 商户调用下单、查询、取消等平台订单接口 |
| `WEBHOOK` | 平台向商户发送异步通知时的签名凭证 |

凭证处理规则：

- 生成后保存 `keyId` 和密钥；密钥只在轮换完成时显示一次，平台不提供明文回读。
- 商户请求使用 `X-Merchant-Key-Id`、`X-Merchant-Timestamp`、`X-Merchant-Nonce` 和 `X-Merchant-Signature`。
- 时间戳允许与服务端相差不超过 300 秒，nonce 不能重复使用。
- 凭证状态为 `ACTIVE` 且未撤销、未过期时才能调用。
- 如配置了源 IP 白名单，商户必须从白名单地址访问网关。
- API 密钥和 WEBHOOK 密钥不能混用，不能写入前端代码、URL、订单 `channelParams` 或日志。

完整请求签名和通知验签规则见 [`merchant-api.md`](merchant-api.md)。

### 7. 创建运行配置版本

后台入口：`版本发布`，以及 `路由与渠道` 中的路由、费率和风控配置。

所有需要进入交易快照的路由、费率和风控规则必须归属同一个待发布版本。推荐操作顺序如下：

1. 创建配置草稿，填写变更原因。
2. 在草稿版本下创建路由规则。
3. 在同一版本下创建费率规则。
4. 在同一版本下创建风控策略。
5. 查看版本差异，确认没有错误的商户、产品、渠道或金额范围。
6. 提交审核 -> 审核通过 -> 正式发布。

版本状态流转：

```text
DRAFT -> IN_REVIEW -> APPROVED -> PUBLISHED
                         \-> 驳回/修订
PUBLISHED -> 回滚生成新的 DRAFT
```

#### 7.1 路由规则

路由用于从产品能力映射到实际渠道，填写：

- 规则 ID 和发布版本。
- 产品编码；如果是商户专属路由，同时填写商户 ID。
- 对客支付方式、国家/地区、交易币种。
- 目标渠道 ID。
- 优先级和流量权重。

同一作用域和优先级的规则按权重分流；优先级数值越小越优先。路由的渠道必须是启用状态，且渠道能力覆盖该国家、币种、支付方式和金额范围。

#### 7.2 费率规则

填写产品、可选商户、可选渠道、交易币种和金额范围，并选择：

- `FIXED` 固定手续费。
- `PERCENTAGE` 比例手续费。
- `TIERED` 阶梯手续费及阶梯 JSON。
- `COMBINED` 比例加固定费用的历史组合模式。

同时配置比例费率、固定费用、额外费用、最小/最大手续费、收费承担方（`PAYER_BEAR`、`MERCHANT_BEAR`、`INCLUSIVE`、`EXCLUSIVE`）和交易金额上下限。金额和费率使用十进制定点数，不使用二进制浮点数表达钱款。

#### 7.3 风控策略

填写策略 ID、名称、优先级、命中动作和条件 JSON：

- `PASS` 明确放行。
- `REVIEW` 转人工审核。
- `REJECT` 拒绝交易。

数值越小越先命中。当前条件可按 `merchantId`、`productCode`、`country`、`currency`、`amountGt`、`amountGte`、`amountLt`、`amountLte` 组合配置。

提交发布前，平台会校验至少存在一条有效路由、费率和风控规则，路由渠道不能停用，金额区间不能冲突。

### 8. 配置商户结算规则

后台入口：`结算管理`。这一步不决定订单能否创建，但决定支付成功后如何形成待结算明细和结算批次，生产上线前必须完成。

结算规则绑定到商户产品，结算币种使用产品默认币种。填写：

- 商户和商户产品。
- 结算周期：自然日、工作日、周结、多周结算、月结或手工结算。
- 延迟天数、星期、间隔周数或每月结算日（按周期显示）。
- 最低结算金额和结算费率。
- 生效日期、失效日期、是否自动结算。

资金账户按“商户 + 币种”创建或复用；不同币种不会共用同一个余额账户。结算规则缺失时，支付成功后的结算明细无法正常进入结算流程。

## 三、商户对接流程

管理后台完成发布后，向商户提供一份接入包：

- 网关公网 Base URL 和环境说明。
- 商户 `API` 凭证的 `keyId` 和一次性密钥。
- 已开通产品的 `appId`、支持的 `payModel`、国家和币种范围。
- 异步通知地址要求、通知验签说明和重试策略。
- 测试金额范围、幂等键要求和技术支持联系人。

商户按以下顺序接入：

1. 使用 API 密钥按 [`merchant-api.md`](merchant-api.md) 生成请求签名。签名原文绑定 HTTP 方法、原始路径、规范化 query、时间戳、nonce 和原始 Body 摘要。
2. 创建订单时传 `appId`、`payModel`、国家、币种、金额和商户订单号；不要传 `productCode`。同时传唯一的 `Idempotency-Key`。
3. 根据创建订单响应继续支付交互。创建成功只代表订单已受理，不代表支付成功。
4. 接收异步通知：先校验 WEBHOOK 签名，再按 `eventId` 做幂等处理；处理成功返回 HTTP 2xx。
5. 无论是否收到通知，都使用查询接口确认最终状态。只有 `SUCCESS` 才能作为收款完成依据。
6. 需要取消或退款时使用对应接口，并为退款请求使用独立且唯一的幂等键。

### 下单前检查清单

- 商户状态为 `ACTIVE`。
- 商户产品绑定为 `ACTIVE`，且使用后台展示的 `appId`。
- `payModel` 已在产品能力中启用，金额处于能力范围内。
- 国家、币种和国家-币种关系为 `ACTIVE`。
- 至少有一条已发布且匹配的路由规则、费率规则和风控规则。
- 路由命中的渠道为 `ACTIVE`，渠道配置和供应商凭证可用。
- 商户 API 凭证未撤销、未过期，nonce 未重复，服务器时间准确。
- `notifyUrl` 使用允许的 HTTP/HTTPS 地址，商户已实现通知验签和幂等处理。

## 四、联调与上线验收

### 测试环境

1. 使用独立测试商户、测试 `appId`、测试 API/WEBHOOK 凭证和测试渠道凭证。
2. 验证成功、失败、超时、取消、重复幂等键、重复 nonce 和非法签名。
3. 验证异步通知重复投递、通知验签失败、商户返回非 2xx 和查询兜底。
4. 验证路由优先级/权重、费率计算、风控 `PASS`/`REVIEW`/`REJECT` 和金额边界。
5. 验证支付成功事件、商户资金入账、结算明细和结算批次。

### 生产上线

- 使用生产渠道和生产密钥替换测试配置，不复制测试密钥。
- 确认渠道供应商已加入生产出口 IP，平台回调地址可从供应商网络访问。
- 确认最终配置版本已审核、发布，且发布差异已留档。
- 确认商户收到的 `appId`、API `keyId`、WEBHOOK 验签资料和通知地址均与生产环境匹配。
- 观察首批订单、通知投递、Outbox、资金入账和结算明细；出现异常时优先暂停商户产品或渠道绑定，不直接修改历史订单或账务记录。

## 五、常见边界

- `appId` 是商户产品绑定的公开标识，不是币种账号，也不替代商户 ID。
- 一个商户可以绑定多个产品并获得多个 `appId`；每个 `appId` 对应一个商户产品绑定。
- 渠道凭证是平台调用供应商所需的凭证；商户 API 凭证是商户调用平台所需的凭证，两者不能混用。
- 停用国家、产品、渠道、路由、商户产品或凭证会阻止相应的新交易入口，但不应删除历史订单、通知或账务记录。
- 变更路由、费率和风控时应创建新的发布版本并保留审计，不要直接覆盖正在使用的历史版本。
