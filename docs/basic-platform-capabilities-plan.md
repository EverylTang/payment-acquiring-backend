# 基础管理平台功能建设规划

> 更新时间：2026-08-21
>
> 适用项目：`payment-acquiring-backend`、`payment-acquiring-frontend`
>
> 本文用于规划收单系统管理后台的基础能力建设，先完成身份、权限和核心主数据管理，再扩展渠道、路由、费率和风控运营能力。本文只记录方案，不自动执行数据库变更，不替代具体接口设计和开发任务。

## 1. 建设目标

当前系统已经具备管理员登录、JWT、角色判断，以及商户、逻辑产品、产品能力、商户产品绑定等支付配置模型，但后台仍以单页控制台和只读列表为主。基础建设阶段需要形成以下闭环：

```text
用户登录
→ 用户/角色/菜单/权限配置
→ 按权限展示菜单和操作按钮
→ 后端接口进行权限校验
→ 商户与产品主数据维护
→ 商户产品绑定和能力配置
→ 审批、发布、审计和运行时生效
```

建设原则：

1. 权限底座先于业务页面，避免先做页面后返工权限模型。
2. 商户主数据与支付配置分离，不能把联系人、凭证等信息全部塞入现有 `merchant` 表。
3. 逻辑产品、产品能力、商户产品绑定分别管理，避免产品定义和商户专属配置耦合。
4. 所有启停和配置变更都保留审计记录；已产生订单关联的数据原则上不物理删除。
5. 前端只负责展示和交互，最终权限、状态和业务规则以后端校验为准。
6. 敏感凭证只允许写入或轮换，不在列表和普通详情中返回明文。

## 2. 当前基础与主要缺口

| 功能域 | 当前基础 | 当前缺口 |
| --- | --- | --- |
| 用户 | `admin_user`、BCrypt、登录、当前用户查询 | 用户 CRUD、启停、密码、角色分配、锁定和审计 |
| 角色 | `admin_role`、用户角色关联、JWT 角色 | 角色管理、角色权限配置、删除约束 |
| 菜单 | 前端静态菜单 | 菜单模型、树查询、排序、路由元数据、角色关联 |
| 权限 | `@PreAuthorize` 粗粒度角色判断 | 权限编码、按钮权限、接口权限、数据范围 |
| 商户 | `merchant` 最小运行模型 | 商户主数据、联系人、回调、凭证、风险等级和关联视图 |
| 逻辑产品 | `logical_product` | 产品 CRUD、状态管理、管理页面 |
| 产品能力 | `product_capability` | 能力维护、范围校验、批量配置 |
| 商户产品 | `merchant_product` 绑定关系 | 绑定/解绑、商户级能力配置、审批发布和审计 |
| 前端 | 登录、工作台、订单、配置只读列表 | 动态菜单、页面路由、表单、分页、按钮权限 |
| 审计 | 配置和部分运维审计基础 | 统一后台操作审计查询和关联操作者 |

## 4. 权限底座规划

### 4.1 权限模型

建议建立五类核心对象：

```text
admin_user       用户
admin_role       角色
admin_menu       菜单
admin_permission 权限点
admin_data_scope 数据范围
```

关联关系：

```text
用户 ←→ 角色 ←→ 菜单
              └→ 权限点
              └→ 数据范围
```

建议新增或完善的关联表：

- `admin_role_menu`
- `admin_role_permission`
- `admin_role_data_scope`
- `admin_menu_permission`
- `admin_operation_audit`

现有 `admin_user`、`admin_role`、`admin_user_role` 应优先复用，通过后续 Flyway 迁移扩展，不修改历史迁移文件。

### 4.2 权限编码

权限编码使用稳定、可读、可审计的资源动作格式：

```text
system:user:list
system:user:create
system:user:update
system:user:disable
system:user:reset-password
system:user:role

system:role:list
system:role:create
system:role:update
system:role:disable
system:role:permission

system:menu:list
system:menu:create
system:menu:update
system:menu:sort
system:menu:disable

merchant:list
merchant:detail
merchant:create
merchant:update
merchant:enable
merchant:disable
merchant:credential:rotate

product:list
product:create
product:update
product:enable
product:disable

merchant-product:list
merchant-product:bind
merchant-product:unbind
merchant-product:update
merchant-product:enable
merchant-product:disable
```

列表、详情、创建、修改、启停、分配、审批、发布应拆成独立权限点，不能只用一个“模块管理员”权限代替。

### 4.3 内置角色建议

保留现有角色编码，并明确默认权限：

| 角色 | 定位 | 默认范围 |
| --- | --- | --- |
| `ADMIN` | 系统管理员 | 全部菜单、权限和数据；可管理用户及角色 |
| `OPS` | 运营人员 | 商户、产品、渠道、路由和配置运营；不可管理系统管理员 |
| `RISK` | 风控人员 | 风控策略、商户风险信息和相关查询 |
| `FINANCE` | 财务人员 | 费率、结算、账务和只读商户信息 |
| `READONLY` | 只读人员 | 授权范围内的列表、详情和工作台查询 |

角色权限默认数据应通过可重复执行的初始化脚本或迁移写入，不能依赖前端硬编码。

### 4.4 数据权限

第一期建议实现三种数据范围：

- `ALL`：可访问全部商户。
- `ASSIGNED`：只能访问角色或用户被分配的商户。
- `SELF`：只能访问本人创建或负责的数据。

数据权限应在后端查询层执行，不能只在前端隐藏数据。订单、商户产品、路由、费率和风控查询都应沿商户维度复用同一套过滤规则。系统管理员和内部运维账号的特殊范围必须显式配置，不能通过用户名判断。

### 4.5 菜单模型

菜单建议支持以下字段：

- `id`
- `parent_id`
- `menu_code`
- `menu_name`
- `menu_type`：目录、页面、按钮
- `route_path`
- `component_key`
- `permission_code`
- `icon`
- `sort_order`
- `visible`
- `status`
- `created_at`
- `updated_at`

目录和页面用于生成前端导航，按钮用于控制操作入口。菜单树接口只返回当前用户有权限且可见的目录/页面；按钮权限可随用户信息或独立权限接口返回。

### 4.6 安全约束

- 密码使用 BCrypt 存储，禁止返回密码哈希。
- 禁止禁用最后一个可用系统管理员。
- 禁止用户给自己分配超出自身权限范围的角色。
- 角色、菜单和权限被引用时禁止直接删除，使用停用或逻辑删除。
- 角色和权限变更后应使权限缓存失效，避免旧权限长期生效。
- 登录失败次数、锁定时间、最后登录时间应落库；具体阈值通过配置管理。
- 所有用户、角色、菜单、权限和凭证操作写入统一审计。

## 5. 用户管理规划

### 5.1 页面能力

- 用户分页列表：用户名、显示名、状态、角色、最后登录时间、创建时间。
- 新增用户：用户名、显示名、初始密码、角色、状态。
- 编辑用户：显示名、状态、角色；用户名不可随意修改。
- 启用/禁用用户。
- 重置密码：生成一次性初始密码或要求首次登录修改。
- 修改本人密码。
- 查看用户操作记录和登录记录。

### 5.2 后端接口建议

```text
GET    /api/admin/v1/users
GET    /api/admin/v1/users/{id}
POST   /api/admin/v1/users
PUT    /api/admin/v1/users/{id}
PATCH  /api/admin/v1/users/{id}/status
POST   /api/admin/v1/users/{id}/reset-password
PUT    /api/admin/v1/users/{id}/roles
PUT    /api/admin/v1/users/me/password
GET    /api/admin/v1/users/{id}/audits
```

所有列表接口使用分页、状态和关键字筛选；用户启停、角色分配和密码重置应采用独立操作接口，便于审计和权限控制。

## 6. 菜单与权限管理规划

### 6.1 菜单管理页面

- 菜单树展示。
- 新增目录、页面或按钮。
- 修改名称、路由、组件、图标、排序和显示状态。
- 启用/停用菜单。
- 维护页面对应的权限编码。
- 查看菜单关联角色。

### 6.2 角色权限页面

角色详情页分为三部分：

1. 菜单权限：勾选可见目录和页面。
2. 操作权限：勾选列表、新增、修改、启停、审批、发布等权限点。
3. 数据范围：选择全部、指定商户、所属范围或本人。

保存时由后端校验菜单、权限点和数据范围是否存在，返回变更摘要并写入审计。

### 6.3 前端改造

- 登录后调用当前用户信息和动态菜单接口。
- 使用路由守卫拦截无页面权限的路由。
- 使用统一权限函数控制按钮显示和禁用状态。
- 未授权接口统一处理为无权限提示，不展示后端堆栈信息。
- 菜单、路由和权限编码集中维护，避免继续在 `App.vue` 中写死业务菜单。

## 7. 商户管理规划

### 7.1 数据模型方向

现有 `merchant` 继续作为支付运行和配置引用的核心标识表。商户主数据建议拆分扩展：

- `merchant_profile`：简称、全称、注册国家、行业、税务信息、风险等级。
- `merchant_contact`：联系人、邮箱、电话和通知类型。
- `merchant_callback_config`：回调地址、事件范围、启用状态。
- `merchant_credential`：凭证摘要、版本、状态、创建和轮换时间；密钥只保存加密值或不可逆摘要。
- `merchant_data_scope`：内部用户或角色可访问的商户范围。

不建议为商户主数据引入物理删除；当商户被订单、产品或配置引用时，只允许停用，并保留历史快照。

### 7.2 页面能力

- 商户分页列表：商户号、名称、状态、结算币种、风险等级、产品数、创建时间。
- 商户详情：基础资料、联系人、回调配置、凭证状态、产品绑定、关联配置和操作记录。
- 新增商户：基础资料、结算币种、默认状态和初始配置。
- 编辑商户：非标识字段和可变配置。
- 启用/禁用商户，并展示影响范围。
- 凭证创建、轮换、撤销；敏感内容仅在创建或轮换时展示一次。

### 7.3 后端接口建议

```text
GET    /api/admin/v1/merchants
GET    /api/admin/v1/merchants/{merchantId}
POST   /api/admin/v1/merchants
PUT    /api/admin/v1/merchants/{merchantId}
PATCH  /api/admin/v1/merchants/{merchantId}/status
GET    /api/admin/v1/merchants/{merchantId}/products
GET    /api/admin/v1/merchants/{merchantId}/audits
PUT    /api/admin/v1/merchants/{merchantId}/callback-config
POST   /api/admin/v1/merchants/{merchantId}/credentials/rotate
POST   /api/admin/v1/merchants/{merchantId}/credentials/revoke
```

商户状态变化必须校验是否存在进行中的配置发布、有效产品绑定或未完成订单，并明确区分“禁止新交易”和“停止全部运营配置”。

## 8. 商户产品管理规划

### 8.1 功能边界

```text
logical_product       定义产品是什么
product_capability    定义产品通用支持什么
merchant_product      定义商户是否开通该产品
merchant_product_*    定义该商户实际允许如何使用
```

商户产品配置可以包含：国家、币种、支付方式、金额上下限、退款能力、状态、生效时间、失效时间，以及关联的路由和费率规则。通用产品能力是上限，商户产品配置不能突破产品能力边界。

### 8.2 页面能力

- 逻辑产品列表和详情。
- 产品新增、编辑、启用、停用。
- 产品能力按国家、币种、支付方式维护。
- 商户产品列表支持按商户、产品和状态筛选。
- 绑定产品：只允许选择有效商户和有效产品。
- 修改商户产品范围、限额、退款能力和状态。
- 解除绑定：需校验订单和配置引用，必要时仅停用。
- 查看商户产品关联的费率、路由、风控和变更记录。
- 提供变更前后差异预览，并进入现有配置发布流程。

### 8.3 后端接口建议

```text
GET    /api/admin/v1/products
GET    /api/admin/v1/products/{productCode}
POST   /api/admin/v1/products
PUT    /api/admin/v1/products/{productCode}
PATCH  /api/admin/v1/products/{productCode}/status
GET    /api/admin/v1/products/{productCode}/capabilities
PUT    /api/admin/v1/products/{productCode}/capabilities

GET    /api/admin/v1/merchant-products
GET    /api/admin/v1/merchant-products/{bindingId}
POST   /api/admin/v1/merchant-products
PUT    /api/admin/v1/merchant-products/{bindingId}
PATCH  /api/admin/v1/merchant-products/{bindingId}/status
POST   /api/admin/v1/merchant-products/{bindingId}/disable
GET    /api/admin/v1/merchant-products/{bindingId}/audits
```

绑定和修改操作应在事务内完成唯一性校验、商户/产品状态校验和能力范围校验。接口应返回绑定 ID、商户号、产品编码、有效范围、状态和当前配置版本，供前端后续关联路由、费率和发布流程。

## 9. 审批、发布与审计

基础管理页面完成增改后，涉及交易运行的配置不直接覆盖线上状态，建议区分：

```text
草稿 → 提交审核 → 审核通过 → 发布 → 生效
                         └→ 驳回/撤回
```

第一期纳入发布流程的对象：

- 商户产品绑定和范围配置。
- 产品能力。
- 路由规则。
- 费率规则。
- 风控策略。

商户名称、联系人等非运行配置可以直接保存，但仍需审计。每次变更至少记录：操作者、角色、请求 ID、对象类型、对象 ID、操作类型、变更前摘要、变更后摘要、结果、失败原因和时间。敏感字段只记录脱敏摘要，不能写入明文。

## 10. 分阶段实施计划

### P0：身份与权限底座

1. 完善用户查询、创建、编辑、启停、重置密码和角色分配。
2. 完善角色管理和内置角色权限初始化。
3. 新增菜单、权限点及角色关联模型。
4. 提供当前用户菜单树、权限编码和数据范围接口。
5. 后端从粗粒度角色判断逐步补充细粒度权限编码。
6. 前端接入动态路由、菜单和按钮权限。
7. 建立统一后台操作审计。

完成标准：不同角色登录后只能看到授权菜单；未授权用户无法通过直接调用接口执行操作；用户、角色、菜单和权限变更可追溯。

### P1：商户主数据

1. 完善商户分页、详情、新增、编辑和启停。
2. 增加联系人、回调配置和凭证轮换能力。
3. 增加商户风险等级和数据范围关联。
4. 前端完成商户列表、表单、详情页和操作确认。
5. 补充商户状态对产品、配置和交易入口的联动校验。

完成标准：运营人员可独立完成商户全生命周期管理，凭证不泄露，停用商户不能创建新交易，历史订单和关联配置可查询。

### P1：产品与商户产品

1. 完成逻辑产品 CRUD 和产品能力维护。
2. 完成商户产品绑定、修改、启停和停用替代解绑。
3. 增加能力范围、金额限额、退款能力和有效期校验。
4. 关联现有路由、费率、风控配置和发布快照。
5. 前端完成产品中心和商户产品详情页。

完成标准：只能将有效产品绑定到有效商户；商户产品配置不能超过通用产品能力；变更可预览、可审核、可发布并可审计。

### P2：运营配置完善

1. 渠道、路由、费率、风控增改启停页面。
2. 配置版本差异、发布审批和正式回滚。
3. 真实渠道健康探测和配置运行时校验。
4. 权限回归、接口集成和浏览器端到端测试。

## 11. API 与前端交付规范

### 后端

- 列表接口统一分页参数、排序参数、筛选参数和响应结构。
- 写接口统一返回资源标识、状态和版本信息。
- 状态变更使用显式动作接口，避免任意修改状态字段。
- 业务冲突返回稳定错误码，例如重复绑定、对象已停用、权限不足、配置被引用。
- Controller 只负责边界转换和鉴权，状态校验放在应用服务和领域逻辑中。
- 新表使用新的 Flyway 迁移，历史迁移文件不回改。

### 前端

- 每个模块拆分列表、编辑表单、详情和权限控制，不继续扩大 `App.vue` 单文件职责。
- 所有表单具备必填、格式、范围和重复提交保护。
- 危险操作要求二次确认，并展示影响范围。
- 列表支持分页、筛选、刷新、空状态、加载状态和错误提示。
- 前端按钮隐藏只是体验优化，后端权限拒绝仍必须正确处理。

## 12. 验收清单

### 认证与权限

- [ ] 登录、退出、当前用户信息和权限刷新正常。
- [ ] 用户 CRUD、启停、密码重置和角色分配正常。
- [ ] 最后一个系统管理员不能被禁用或降权。
- [ ] 菜单树按角色返回，页面直达和接口直调均受保护。
- [ ] 按钮权限、接口权限和数据范围均有后端校验。
- [ ] 权限变更后缓存及时失效。

### 商户与产品

- [ ] 商户可新增、编辑、启用、停用和查看详情。
- [ ] 商户凭证创建、轮换、撤销和脱敏展示正常。
- [ ] 产品和产品能力可维护并有范围校验。
- [ ] 商户产品可绑定、修改、启停和查看关联配置。
- [ ] 重复绑定、无效商户、无效产品和超范围配置会被拒绝。
- [ ] 被订单或配置引用的对象不能物理删除。

### 运营与审计

- [ ] 运行配置变更进入草稿、审核和发布流程。
- [ ] 可查看变更差异和发布版本。
- [ ] 用户、角色、权限、商户和产品操作均有审计记录。
- [ ] 审计记录包含操作者、请求 ID、对象、结果和时间。
- [ ] 敏感信息不会出现在接口响应、日志和审计明文中。

## 13. 首批开发任务建议

建议第一轮不要同时铺开所有业务模块，按以下顺序拆分迭代：

1. 后端：用户、角色、菜单、权限点数据库迁移和查询模型。
2. 后端：当前用户权限接口、用户/角色管理接口和细粒度权限校验。
3. 前端：动态菜单、路由守卫、按钮权限指令和用户/角色页面。
4. 后端：商户分页、详情、CRUD、启停和统一审计。
5. 前端：商户列表、表单、详情和关联产品页面。
6. 后端：逻辑产品、产品能力、商户产品绑定及范围校验。
7. 前端：产品中心、商户产品管理和配置差异展示。
8. 联调：角色矩阵、状态联动、重复提交、越权访问和审计回归。

以上任务完成后，再进入渠道、路由、费率和风控的完整管理页面建设。
